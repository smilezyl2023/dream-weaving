# Stage 01 — Idea Crystallization（想法澄清）

> **本阶段职责**：把用户最初那句模糊的"我想做 X"澄清成一个**可被检验**的产品命题。产物是 `01-idea.md`。
>
> **核心理念**：YC 创始人 Paul Graham 说大多数失败的创业是"从答案开始而不是从问题开始"。这一阶段唯一的工作是**把问题想清楚**，不是急着定义产品。

---

## 入口检查

1. Read `<cwd>/product/<slug>/00-state.md`，强制读取 `## profile` 节
2. 确认 Phase 0 已完成（`profile-completed` 标记存在）
3. Read 用户在主 SKILL.md 启动时记下的「一句话定位」（在 `00-state.md` 的「一句话定位」节）

---

## 步骤 1：开场（基于 profile 调整语气）

**编程"无" + 产品"无"**：
```
🌱 我们先把你的想法想清楚一点，再看怎么实现。

你最开始说："{{原始想法}}"

我会问你几个看起来"有点烦"但很重要的问题。
回答的时候不要怕粗糙，越具体越好——比如说"给所有人用"不如说"给我妈那种 60 岁不太会用手机的人用"。
```

**PM / 独立开发者**：
```
进入 Phase 1：把命题钉死。

你的初始描述："{{原始想法}}"

我会用 6 个维度逼你澄清。回答可以不完整，我们用 AskUserQuestion 一轮一轮过。
```

---

## 步骤 2：苏格拉底式追问（6 维度，分 2-3 轮 AskUserQuestion）

**严格遵守**：每次 AskUserQuestion 最多 2 个问题；用户回答模糊就**追问到具体场景**，不要满足于"差不多"、"大概"、"一般人"。

### 第 1 轮：核心命题（必问）

| 问题 | 追问触发条件 |
|------|------------|
| **Q1.1 解决什么问题？** 用一句话描述用户当前**正在受什么苦**（不是"想要什么功能"） | 如果回答只描述了功能（"我想做一个 X 工具"），追问："那这个工具帮用户**避免**了什么麻烦？" |
| **Q1.2 给谁？** 描述一个具体的人（年龄、职业、生活/工作场景） | 如果回答是"所有人"、"年轻人"、"打工人"，追问："给我画一个具体的画像——TA 一天里什么时候最可能用到这个？" |

### 第 2 轮：动机和现状（必问）

| 问题 | 追问触发条件 |
|------|------------|
| **Q2.1 现在他们怎么解决这个问题？** 列出 1-3 个替代方案（手动 / Excel / 现有产品 / 不解决） | 如果回答"没人解决过"，追问："那他们不解决会怎样？还是说他们其实在用 {{某种繁琐方式}}？" |
| **Q2.2 你为什么想做这个？** 个人动机（自己被这个问题困扰过 / 看到别人受困 / 商业机会 / 学习练手） | 如果回答"觉得有市场"，追问："你自己用这个产品的频率会是多少？一周一次？一天一次？" |

### 第 3 轮：边界和反方（必问）

| 问题 | 追问触发条件 |
|------|------------|
| **Q3.1 这个想法最容易被否定的一点是什么？** 自己当反方：为什么这件事不该做 / 为什么用户不会用 | 如果用户答不上来，**你**主动给出 2-3 个反方观点让用户回应 |
| **Q3.2 一年后如果这个产品成功了，你会用什么数字证明？** 不要 vague 数字（"很多人用"），要具体（DAU 1000 / 月留存 30% / 自己天天在用） | 如果回答"很多人用"或"赚钱"，追问："具体多少人？多少钱？多久能达到？" |

## 步骤 3：写入 `01-idea.md`

用以下模板。**严格使用用户原话**填充，不要润色到"听起来像 PRD"——这一阶段就是要保持原始想法的鲜度和不确定性。

```markdown
# 01 Idea Crystallization

> 创建日期: {{date}}
> 状态: {{DRAFT | LOCKED}}
> 用户原始描述: "{{用户在 00-state 的"一句话定位"}}"

## 一句话产品命题

> 模板：**为 [谁]** 解决 **[什么问题]**，做法是 **[一句话方案]**，因为 **[当前替代方案]** 不够好。

为 {{具体用户画像，1-2 句}} 解决 {{用户当前正在受的苦，1 句}}，
做法是 {{一句话方案}}，
因为 {{当前替代方案}} 在 {{什么维度}} 上不够好。

## 目标用户（一个具体的人，不是人群）

- **画像**: {{年龄/职业/生活场景}}
- **触发场景**: TA 一天里什么时候、在什么状态下会想到这个问题？
- **当前替代**: TA 现在怎么应付？为什么应付得不好？

## 用户当前的"苦"

> 不是"用户想要什么"，是"用户当前每天/每周在受什么具体的麻烦"。

- {{苦 1：场景 + 代价}}
- {{苦 2}}
- {{苦 3}}

## 我（创造者）的动机

- {{为什么是我做这个？个人故事/技能/资源}}
- 我自己用的频率会是: {{每天/每周/偶尔}}

## 反方观点（自己拆台）

> 至少 3 条。这一节是为了防止 confirmation bias。

1. **反对意见 1**: {{为什么这件事不该做}}
   **回应**: {{用户的回应或"目前没好答案"}}
2. **反对意见 2**: ...
3. **反对意见 3**: ...

## 一年后的成功标准

具体到数字：
- {{量化指标 1，如 "100 个真实用户每周打开"}}
- {{量化指标 2}}

## 待验证的关键假设（Phase 2 调研要解答这些）

- [ ] {{假设 1：是不是真的有人在受这个苦}}
- [ ] {{假设 2：现有方案是不是真的不够好}}
- [ ] {{假设 3：用户是不是愿意为新方案改变习惯}}
```

## 步骤 4：回放 + 校对

写完 `01-idea.md` 后输出：

```
✅ Phase 1 产物已写入 product/{{slug}}/01-idea.md

核心命题：
  {{一句话产品命题}}

我故意把它写得很"窄"（"为 [非常具体的人] 解决 [非常具体的苦]"）——这样后面调研和决策才有抓手。

如果命题太窄漏掉了你想做的范围，回复"调宽一点"。
如果觉得对了，回复"go" 或 /dream-weaving next 进入 Phase 2 市场调研。
```

---

## 步骤 5：Exit gate

满足以下条件才能进入 Phase 2：

- [x] `01-idea.md` 写完且非空
- [x] "一句话产品命题" 不含"所有人"、"很多人"、"一般人"等模糊词
- [x] "反方观点" 节至少 3 条
- [x] "待验证的关键假设" 节至少 2 条
- [x] 用户已确认（"go"、"对"、"进 Phase 2" 等）

满足后：
1. `00-state.md` 阶段进度勾选 Phase 1
2. 在 `00-state.md` 决策快照表追加一行：`Phase 1 | {{date}} | {{一句话命题}}`
3. 等待用户发 `/dream-weaving next`，**不自动推进**（给用户喘息和考虑的时间）

---

## 反例（永远不要这样做）

- ❌ 写出 PRD 风格的"功能列表"（那是 Phase 5 的事）
- ❌ 接受"给所有人用"作为目标用户
- ❌ 跳过反方观点这一节
- ❌ 用户回答模糊就直接写到产物里（必追问）
- ❌ 把命题写得很大（"重新定义 X 行业"）
- ❌ 在 Phase 1 讨论技术栈、设计风格、商业模式（那是后面的阶段）
