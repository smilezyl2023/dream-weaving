# Stage 06 — Design System & UX Flow（设计系统 + 关键流程）

> **本阶段职责**：定义美学方向、关键 UX 流程、组件库选型，产出 `06-design.md`，可选产出 `06-design-preview.html` 视觉预览页。
>
> **核心理念**：MVP 阶段不重新发明视觉语言。**复用成熟系统 + 一个特别的差异化点** 比"我自己设计"高效 100 倍。

## 步骤 1：开场（按 profile 分流）

**设计"无"**（推荐成熟系统）：
```
进入 Phase 6：定 V1 的样子。

我不会让你"从 0 设计"——会推荐你套现成的视觉系统，再告诉你怎么改 1-2 处让它有自己的样子。

最常见的 3 条路：
  A. Tailwind + shadcn/ui — 互联网产品标配，AI 生成代码默认风格，零成本起步
  B. Material Design 3 — Google 系，安卓友好，文档详尽
  C. Apple HIG / Human Interface — iOS/Mac 友好，强对话感

V1 通常选 A（最省力 + AI 友好）。我会问几个问题确认。
```

**设计"会用 Figma" / "专业"**：
```
进入 Phase 6：DESIGN.md。

我会跟你过 6 个维度（美学方向 / 排版 / 色彩 / 间距 / 状态 / 响应式）+ 你提供素材或 references。
最终产物含完整 DESIGN.md 模板，你 V1 可以直接交给开发者或 AI 实现。
```

## 步骤 2：AskUserQuestion 收集设计方向（1-2 轮）

### 第 1 轮：美学方向

```
问题 1：你希望产品给用户的"第一感"是什么？（最贴近的一个）
- 干净/极简（白底 + 黑字 + 大量留白，如 Notion / Linear）
- 温暖/柔软（柔和色 + 圆角 + 插画感，如 Headspace / Duolingo）
- 严肃/专业（深色 + 数据感 + 紧凑，如 Bloomberg / Datadog）
- 活泼/年轻（鲜艳 + 渐变 + 动态，如 TikTok / Discord）
- 复古/手工（衬线字体 + 纸感 + 不规则，如 Are.na）

问题 2：暗黑模式？
- 必须有（夜间用得多）
- 想有但 V1 可以先没（太麻烦）
- 不需要（场景就是白天）
```

### 第 2 轮（仅设计经验为"无"）：差异化锚点

```
问题：你希望用户能在 5 秒内"记住"你产品的什么？（一个就够）
- 一个特别的颜色（用户说"那个紫色的 app"）
- 一个特别的形状/icon（如 Notion 的"N"）
- 一句特别的话（slogan）
- 一种独特的交互（如左滑/抽屉/卡片）
- 不重要，先把功能做出来
```

## 步骤 3：根据 profile 决定推荐方案

| profile | 推荐方案 | 理由 |
|---------|---------|------|
| 设计"无" + 平台"Web" | Tailwind + shadcn/ui，色调 = 中性 + 1 个品牌色 | AI 编程工具最熟，生成代码即可用 |
| 设计"无" + 平台"小程序" | 套微信原生 WeUI / TDesign | 平台原生，老人也熟悉 |
| 设计"无" + 平台"iOS" | Apple HIG + SwiftUI 默认组件 | 平台一致，审核友好 |
| 设计"会用 Figma" | 同上，但允许用户提交自己的 Figma 链接作为 reference | 留出定制空间 |
| 设计"专业" | 用户主导，skill 只产出 DESIGN.md 模板让用户填 | 不抢专业人的活 |

## 响应式断点（Web）

| 断点 | 范围 | 主要适配点 |
|------|------|----------|
| Mobile | < 640px | 单列、底部 tab、大按钮 |
| Tablet | 640-1024px | 双列、可选侧边栏 |
| Desktop | > 1024px | 三列、固定侧边栏 |

> V1 推荐：先做 Mobile-first，桌面端兼容（80% 用户场景已覆盖）

## 反例

- ❌ 让设计经验为"无"的用户从零选字体/色卡（应该推荐）
- ❌ V1 列 30 个组件（先列 P0 流程必须的就够）
- ❌ 跳过失败路径（loading / error / empty 必须有）
- ❌ 给设计专业人塞一套通用模板（让对方主导）
- ❌ 流程图写成"用户进入 → 做事情 → 结束"的废话
