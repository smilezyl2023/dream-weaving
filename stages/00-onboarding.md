# Stage 00 — Onboarding（用户画像评估）

> **本阶段职责**：建立用户画像 (profile)，写入 `00-state.md` 的 `## profile` 节。后续所有阶段都依赖此 profile 决定解释深度、术语门槛、推荐倾向。
>
> **触发**：新建产品时由主 SKILL.md 自动进入；也可通过 `/dream-weaving back 0` 重新评估。
>
> **预计耗时**：3-5 分钟。

---

## 入口检查

1. 确认 `<cwd>/product/<slug>/00-state.md` 存在；不存在则停止并报错（应由主 SKILL.md 启动新产品时已创建）
2. 读 `00-state.md`，检查 `## profile` 节是否已填完整
3. 如已填完整 → 跳过本阶段，直接进入 Phase 1
4. 如未填或不完整 → 继续步骤 5

---

## 步骤 5：发出欢迎并解释 onboarding 的目的

输出（按用户原始想法的复杂度选 1-2 句）：

```
👋 准备开始把这个想法织成产品。

在动手之前，我需要先了解你 4 件事，这会决定我后面用什么深度跟你解释、推荐什么方案。
（不是测验，没有标准答案，凭直觉选最贴近你的就行）
```

---

## 步骤 6：AskUserQuestion 收集 4 个维度

**重要**：用 AskUserQuestion 一次性问 4 个问题（multiSelect: false）。**不要分多轮文本提问**。

```
问题 1：你的编程经验？
- 完全没有（不会写代码）
- 会一点（HTML/Python/SQL/能改改别人的代码）
- 熟练（前端 / 后端 / 全栈，能独立做项目）
- 资深（多年经验，关注架构和性能）

问题 2：你之前用过哪些 AI 编程工具？
- 没用过 / 只用过 ChatGPT 聊天
- 用 ChatGPT/Claude 写过代码片段（粘贴执行）
- 用过 Cursor / Claude Code / Codex 这类 AI IDE
- 用过 Lovable / Bolt / v0 / Replit Agent 这类一键出 app

问题 3：你的产品/创业经验？
- 完全没有（这是第一次做"产品"）
- 公司 PM / 项目经理（懂用户故事 / PRD）
- 独立开发者 / 副业做过产品
- 创过业 / 带过完整产品周期

问题 4：你的设计经验？
- 完全没有（说不出审美偏好）
- 会用 Figma / Sketch 改改稿
- 专业设计师（系统的视觉训练）
- 会但只追求"能用"（不在意美观）
```

---

## 步骤 7：补问目标平台和预算（如需要）

如果用户在问题 1 选了"完全没有"或"会一点"，**追加** AskUserQuestion 问目标平台：

```
你想做的东西最终给谁用？最容易在哪里使用？
- 给我自己 / 家人朋友用，电脑或手机浏览器打开就行（→ Web）
- 微信里用（→ 小程序）
- 苹果手机用（→ iOS）
- 安卓手机用（→ Android）
- 命令行 / 自动化脚本（→ CLI）
- 不确定，你帮我推荐
```

如果是其他经验等级且用户原始描述里没明确平台，**也问一次**这个问题（但选项可以更技术化）。

如果用户原始想法中已明确平台（如"做一个微信小程序"），跳过此问题。

---

## 步骤 8：把答案写入 `00-state.md`

用 Edit 工具更新 `00-state.md` 的 `## profile` 节。把上面 4-5 个问题的答案填入对应 bullet。

**关键约束**：
- 严格使用用户原文（如"会一点"、"PM"），不要意译
- 不要添加用户没说的推断（如不要写"应该是技术小白"）
- 末尾追加一行 `> profile-completed: <YYYY-MM-DD>` 作为门禁标记

---

## 步骤 9：用大白话回放给用户

根据 profile 总结一句话回放，让用户校对：

模板：
```
✅ 好了，我对你的画像是：
   {{编程经验}} + {{产品经验}} + {{设计经验}} + 想做 {{平台}}。

后面我会这么配合你：
- {{自适应规则的 1-2 条具体应用}}

如果不准就回复"改一下"，否则我们直接进入 Phase 1：把你的想法澄清清楚。
```

**示例**（编程"无" + 产品"无" + 设计"无" + Web）：
```
✅ 好了，我对你的画像是：
   不会写代码 + 第一次做产品 + 没设计经验 + 想做电脑/手机网页能用的工具。

后面我会这么配合你：
- 任何技术词出现前我都会用类比解释
- 推荐零代码或半托管方案，不让你折腾服务器
- 设计上直接套成熟模板，先把功能跑起来

如果不准就回复"改一下"，否则我们直接进入 Phase 1。
```

**示例**（PM + 会一点编程 + 会 Figma + Web）：
```
✅ 你是 PM、会写一点代码、会用 Figma，准备做一个 Web 产品。
   后面我会用 PRD/JTBD/user story 等术语直接对话，技术选型给你推荐路线但不展开教学。
   进入 Phase 1。
```

---

## 步骤 10：Exit gate

满足以下条件才能进入 Phase 1：

- [x] `00-state.md` 的 `## profile` 节 4 个 bullet 已填
- [x] `> profile-completed: <date>` 标记已写入
- [x] 用户已确认画像准确（"对"、"嗯"、"go"、"进 Phase 1" 等任一明确肯定回复，或 5 秒内未反对）

满足后：
1. 在 `00-state.md` 的阶段进度表把 Phase 0 勾选 `[x]`
2. **直接 Read `stages/01-idea.md` 进入 Phase 1**（不需要用户再发命令）

---

## 反例（永远不要这样做）

- ❌ 没等用户确认 profile 准确就进 Phase 1
- ❌ 把 4 个问题分 4 轮文本提问而不用 AskUserQuestion
- ❌ 推断用户没说的内容（如用户选"会一点"就脑补成"前端开发"）
- ❌ Phase 0 里就开始讨论想法本身（那是 Phase 1 的事）
- ❌ 跳过目标平台询问（即使用户没问起，也要补问）
