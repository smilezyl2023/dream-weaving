# Stage 11 — User Validation（用户验证）

> **本阶段职责**：把 V1 拿给真实用户用，验证 PRD 的成功指标和 JTBD 的 Main Job 是否真的被解决。产物是 `11-validation.md`。
>
> **核心理念**：**3-5 个真实用户的反馈** > 100 次自我说服。这一阶段最常见的错误是"觉得验证不必要 / 自己用就行"。

---

## 入口检查

1. Read `00-state.md`，确认 Phase 9 全部任务 `[✅]`
2. Read `04-jtbd.md`（Main Job + 验证方法）
3. Read `05-prd.md`（成功指标）

---

## 步骤 1：开场 + 确定验证范围

```
进入 Phase 11：用户验证。

V1 已经能跑了。接下来不是急着上线，而是先找 3-5 个真实用户用 1-2 周，看 Phase 4 写的 Main Job 是不是真的被解决。

这一步如果跳过，你后面优化的方向 100% 是猜的。
```

AskUserQuestion：

```
问题 1：你能找到几个真实目标用户测试 V1？
- 0 个（自己一个人用）
- 1-2 个（家人/朋友）
- 3-5 个（小范围）
- > 5 个（已有种子用户）

问题 2：验证周期？
- 1 周（快速看反馈）
- 2 周（推荐，看留存）
- 1 个月（用户少时给足够时间）
```

如用户答"0 个" → 强烈建议至少找 1-2 人；如用户坚持自测 → 在 `MEMORY.md` 写 1 条 decision 记录"V1 仅自测"风险。

## 收集反馈的方式

## 必问的 5 个问题（访谈用）

1. **回顾用法**: 你最近一次用 {{产品名}} 是什么时候？为了做什么？
2. **替代对比**: 在没有这个工具之前，你是怎么解决这件事的？哪种更好？
3. **未满足**: 用的过程中有没有什么"想做但做不到"的事？
4. **推荐意愿**: 你会不会推荐给和你处境类似的人？为什么？
5. **去掉测试**: 如果明天我把这个工具下线，你会不会有点难受？

## 步骤 3：用户使用期间的"轻陪伴"

在 1-2 周验证期内，skill 不主动驱动。只在用户运行 `/dream-weaving status` 时提示：

```
Phase 11 验证进行中（第 X 天 / {{N}} 天）

待跟进的用户:
- U-1: 还没收到反馈，建议主动联系
- U-2: 已使用 3 次，反馈已记录

回复 /dream-weaving back 11 进入验证记录页填新反馈。
```

---

## 步骤 4：验证结束 → 回放结论

验证周期结束 → AskUserQuestion 让用户做决策：

```
问题：基于 11-validation.md 的反馈汇总，下一步？
- V1 验证通过，进 Phase 12 准备发版
- V1 需要小修，回 Phase 8 加新 task（不重新规划）
- 反馈很差，回 Phase 1 重新审视命题（可能要 pivot）
```

---

## 步骤 5：Exit gate

- [x] `11-validation.md` 写完
- [x] 至少 1 个真实用户的反馈（即使是自测，也要记录"自测发现"）
- [x] 量化指标对比表填写
- [x] "结论" 节有明确的 Main Job 解决度判断
- [x] 用户做出下一步决策

满足后勾选 Phase 11、追加决策快照。

---

## 反例

- ❌ 直接跳过 Phase 11 进 Phase 12
- ❌ 用 0 个真实用户就标"验证完成"
- ❌ "结论"节写"反馈不错"（必须量化）
- ❌ 不收集用户原话，全是自己的转述
- ❌ 验证发现失败信号还硬上线
